# Scripts run in Herdr through our own entry point, not by intercepting VS Code tasks

VS Code's built-in **Run Script**, `tasks.json` tasks, and every other task go through `terminal.integrated.automationProfile.<os>`. That setting only accepts an executable `path` and cannot point at an extension terminal profile. Intercepting tasks would need a wrapper executable, and VS Code would still show its own task terminal with duplicated output. Instead the extension adds its own **Run Script in Herdr** action (in the NPM Scripts view and in a `package.json` hover). The action builds the command the way VS Code does and runs it in a new Herdr Tab, while the built-in Run Script keeps opening plain VS Code terminals. See `docs/research/issue-39-vscode-terminals-and-npm-scripts.md`.
