## Findings

- **Documented guarantee:** [`terminal session observe`](https://herdr.dev/docs/cli-reference/#direct-terminal-attach) is read-only and prints NDJSON `terminal.frame`, then `terminal.closed` **when the server closes the stream**. The docs do not say that the Pane has been removed, specify a closed-reason enum, or define retryability. The official [persistence documentation](https://herdr.dev/docs/persistence-remote/#direct-terminal-attach) allows multiple concurrent observers of one terminal.
- **Pinned-source observation:** the [v0.9.0 CLI client](https://github.com/herdrdev/herdr/blob/v0.9.0/src/client/terminal_sessions.rs) serializes `terminal.closed` with an optional, free-form reason on `ServerShutdown`. [Graceful server shutdown](https://github.com/herdrdev/herdr/blob/v0.9.0/src/server/headless/lifecycle.rs) emits such a record (`server is shutting down`); [target-resolution failure](https://github.com/herdrdev/herdr/blob/v0.9.0/src/server/headless.rs) also ends the stream with a reason. The CLI can exit successfully on a protocol close, while an unexpected EOF can also yield exit 0 without that record ([CLI command](https://github.com/herdrdev/herdr/blob/v0.9.0/src/cli.rs), [stream output](https://github.com/herdrdev/herdr/blob/v0.9.0/src/client/terminal_sessions.rs)). **Exit status, stream closure and server Pane state are different facts.** No reliable public `terminal.closed` reason taxonomy or proof that Pane removal always emits this record was found.
- **Documented guarantee:** after a full server stop/restart, the [session shape](https://herdr.dev/docs/session-state/#snapshot-restore) can be restored, but the original Pane processes are gone. [Screen-history replay](https://herdr.dev/docs/session-state/#pane-screen-history-replay) is optional and restores recent content, not the old process; native Agent session restore has its [own conditions](https://herdr.dev/docs/session-state/#native-agent-session-restore).
- **Pinned-source observation:** the [saved snapshot](https://github.com/herdrdev/herdr/blob/v0.9.0/src/persist/snapshot.rs) does not preserve terminal IDs; [normal restore](https://github.com/herdrdev/herdr/blob/v0.9.0/src/persist/restore.rs) remaps internal Pane IDs and allocates a [new terminal ID](https://github.com/herdrdev/herdr/blob/v0.9.0/src/terminal/id.rs). Public Pane identity may appear the same after successful restore because public pane-number mappings are persisted, but this is implementation observation, not a stability guarantee. Never assume an old `(Session ID, terminal ID)` is the restored terminal.
- **Available authoritative source:** the [Socket API](https://herdr.dev/docs/socket-api/) provides a fresh `session.snapshot`; the [v0.9.0 Pane schema](https://github.com/herdrdev/herdr/blob/v0.9.0/src/api/schema/panes.rs) exposes Pane ID and terminal ID together. Reconciling a restored Pane with its new terminal is a *product identity policy*, not something the observer's exit code can decide. Herdr does not specify an observer-specific retry delay/budget.

## Limits and design implications

- A transient observer/transport loss can be retried for the **same** terminal. A `terminal.closed` during server shutdown does not imply permanent tombstone; do not suppress retry solely because the CLI exited successfully.
- If a fresh authoritative snapshot no longer contains the original terminal ID, an editor keyed by that ID cannot silently reattach to a *different* terminal without an explicit design decision about Pane identity and replacing the editor's target. Parent #9 expects final screens to remain inspectable when a Pane is gone.
- After switching Navigation to another Session, the current `ActiveSessionProjectionSource` does not expose a fresh projection for the editor's *previous* Session. How to verify that previous Session's Pane without mutating active selection remains a design question; do not quietly couple editor lifecycle to current navigation selection.
- Current unversioned CLI docs mention a 30-second stalled observer write timeout, but the [archived 0.9.0 reference](https://github.com/herdrdev/herdr/blob/master/docs/versions/0.9.0/website/src/content/docs/cli-reference.mdx) and examined [v0.9.0 transport](https://github.com/herdrdev/herdr/blob/v0.9.0/src/server/client_transport.rs) do not establish it for the pinned binary.
