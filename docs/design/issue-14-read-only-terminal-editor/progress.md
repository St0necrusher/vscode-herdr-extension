## Agreed reconnect direction and implemented result

- One editor is keyed by `(Session ID, terminal ID)` and reattaches only to that exact terminal ID. `terminal.closed`/exit end an observer stream, not necessarily the editor or server Pane.
- A fresh connected Sessions snapshot for the **same** Session with that terminal ID absent confirms removal of the editor's target: keep the final screen, stop retries, leave the editor inert. A full server restart produces a new terminal ID: never silently rebind this editor; the user opens the replacement by clicking again.
- While a disconnected editor's Session is selected in Navigation or that editor is focused, retry the same target with capped backoff. When Navigation switches to another Session and that editor is not focused, **pause attempts**; do not poll the old Session in the background. Switching Navigation alone never closes an existing live observer. Returning to that Session or focusing the editor resumes attempts. A successful retry waits for a fresh full frame and resets local viewport/scrollback. Closing the editor cancels retries and disposes only client resources.
- The user explicitly rejected pointless background attempts for an unfocused editor of another Session. This scoped agreement is not approval of the complete #14 design; exact UI copy and remaining seam questions are still open.
- The user accepted the next responsibility split: `PanesFeature` invokes `PaneTerminalOpening` directly (no event bus); `TerminalSurfacesFeature` owns surface registry, per-surface lifecycle, eligibility and retry timers; Herdr CLI infrastructure runs/parses **one** observe subprocess attempt and reports its outcome. Checked the installed VS Code type contract: `Pseudoterminal.close()` responds to user editor closure, while firing `onDidClose` disposes the terminal; therefore stream loss must never fire it when the final screen should remain.
- Agreed surface variants: connecting, live, disconnected/waiting, disconnected/paused, ended, and faulted. Confirmed terminal absence and invalid observer output retain the editor/final screen and stop automatic retry; a later explicit Pane click may retry a faulted existing surface. Additive unknown records are logged/ignored, while invalid JSON or an invalid known frame faults and reaps the attempt.
- The user selected the Sessions retry cadence: immediate, then 0.5/1/2/5/10/30 seconds with ±20% jitter, capped at repeating 30-second attempts while relevant. The policy remains local rather than extracting a generic scheduler.
- The user selected concise terminal-local status: at most one line for the first read-only input attempt and each reconnecting/paused/ended/faulted transition, no toast noise; detailed diagnostics stay in Output. Successful reconnect clears client-local status with the viewport/scrollback reset before the fresh full frame.
