# Issue #19: Herdr Tab layout projection — progress

## State

Redesign in progress. PR #72 implements the first policy (additive projection inside the active group, ADR 0017). The owner rejected that policy after review; the PR stays open and will be reworked on the same branch.

## Owner decisions (2026-10-10)

- Trigger: a click on a Tab row in the Panes View.
- The Tab's layout becomes the whole editor grid: one group per Pane, same split directions and nesting.
- Existing editor groups are reused in grid order: the first group becomes the first Pane's group, and so on. Their file editors stay in them, behind the terminal.
- Surplus groups merge into the last group. Example: 5 open groups, a 4-Pane Tab: the last group holds the editors of groups 4 and 5.
- Mismatched shapes are fine. Example: left|right groups, a top/bottom Tab: the left group's editors end up in the top group, the right group's in the bottom group.
- An already-open Pane Editor of the Tab is moved into its Pane's group, never duplicated.
- Final focus: the Herdr-focused Pane. If that is impossible beyond the eighth group, focusing the last group is acceptable; research a real way first.
- Process: full `build` flow again — research/prototype, design, architect readiness, delegated implementation (pi, sol), review. The main session coordinates itself (no separate coordinator tab).
- Design approval is delegated: the design is validated against the architect instead of the owner. The architect's review of `architecture.md` replaces the owner's approval at the `build` step 2 exit.
