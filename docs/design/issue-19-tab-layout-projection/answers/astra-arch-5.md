# astra-arch-5 — hidden-merge identity amendment

## Summary

- **Amendment: withdraw option A as sufficient for #19.** Hidden merged editors demonstrably never rebind; this is a blocking supported-path defect, not the accepted transient restart.
- Fix identity and bound-tab activation/closure in **pane-editors in this PR**, before further acceptance.
- **Do not ship the proposed “most recent same-label tab” pairing as identity.** The report itself supplies a wrong-terminal counterexample.
- Choose a persistent, unique, manager-owned identity marker in each Pane Editor's published terminal title, alongside the readable Pane name; prototype this contract before implementation dispatch.
- Rebind only by that exact marker, never by display name or recency. Accept the visible identity suffix as the explicit product trade-off.
- Use bound-tab activation for hidden editors; close bound editor tabs through the tab API. Heal lazily, not by activating every merged terminal.
- Final placement may activate each target group in sequence; restore the requested Herdr-focused Pane last. No preserve-focus round trip per cell is required.
- Readiness remains **blocked** on the targeted evidence below; the reported 87/87 does not cover these missing behaviors.
- #73 is related but **not automatically closed**; its actual acceptance criteria and continuity evidence must be checked.

## Why the previous decision changes

**Amendment.** `bug-tab-switch-1.md` isolates a supported 12 → 13 → 12 sequence: the layout succeeds, but `waitForPaneTab` cannot acquire hidden p6B. `hidden-merge-rebinding.md` explains and reproduces the registry failure, including ineffective rename/show/dispose. The premise of astra-arch-2—eventual unambiguous rebinding through the synthetic-name round trip—is false for this case. The same-Terminal safety requirement remains; an indefinitely unbound terminal does not satisfy it.

## Mechanism and trade-off

**Amendment — stable published identity, not inferred identity.** Retain a unique marker in the terminal title for its entire managed lifetime, with the human Pane name as the readable portion. Use one reserved, explicit suffix format generated by the resource owner; include a per-surface unique token rather than relying on globally unique Pane display names. The marker is immutable across Pane rename and group moves. All name publications, including initial creation, must retain it. Initial binding and replacement-tab binding use exact marker equality, with uniqueness checked; never a naked display-name match.

This intentionally changes visible titles. I accept that small, visible cost on the owner's behalf rather than silently risking binding a user's terminal to the wrong Pane. Do not use invisible Unicode tricks, repeated transient renames, private VS Code IDs or a guessed recency association. The exact readable suffix format belongs in the amended design before dispatch. Do not promise resistance to a user deliberately copying the exact full marker; this is resource correlation in the local UI, not an authentication boundary.

A hidden orphan retains its old published title, which is sufficient **if the immutable marker was already present before the move**. A Pane rename can remain visually stale until activation without losing identity. This is a proposed mechanism supported by the diagnosed failure mode, **not a claimed prototype result**; the gates below must establish it.

### Why the pairing prototype is not enough

Its retained `fresh` set does answer my earlier mechanical criticism of previousTabs being overwritten between open and close. It retains a target across intervening change/group events. It does **not** establish identity: a new, unmanaged same-label terminal followed by a genuine close can still be consumed as the replacement. The report explicitly acknowledges this. Four twins moved in the expected sequence prove that sequence, not the absence of unrelated opens/closes or snapshot ambiguity.

Do not fall back to “most recent” when exact identity is missing. An ambiguous or missing marker must never claim another terminal; preserve failure visibility rather than turn a timeout into wrong-Pane input. Bounded event waiting is appropriate for host propagation, not a license to guess.

## Ownership and observable invariants

- **Manager:** owns Terminal↔Tab association, exact marker lookup, group/tab activation, visibility projection and explicit editor-tab closure. No sessions peer import, feature-owned identity table or projection-only binder.
- **Surface:** owns the terminal and its published title; every title contains the immutable identity marker. The manager receives the needed identity through the existing surface ownership boundary, not a second mutable label store.
- **Feature:** still owns descriptor application and overall placement/final focus. No retries, longer timeout, alternate layout, terminal recreation or arbitrary-terminal activation to recover identity.
- **Guarantees:** same surface/Terminal, correct binding for equal display names, at most one concurrent client, correct actual visibility, no orphan editor left after an explicit close, final requested Pane focused.
- **Continuity:** do not deselect solely because VS Code replaced a Tab object when its exact replacement can be identified. Actual visibility changes may stop/start clients; geometry may restart Observers. No universal zero-restart guarantee.

## Required evidence before dispatch

1. Retained real 12 → 13 → 12 regression; same Terminals and exact final cells/focus.
2. Multiple equal-name managed editors merged hidden, plus an unmanaged terminal with the same human name: correct associations without recency matching.

4. Hidden rename then reveal: unchanged marker, latest readable title after healing, active-terminal context works.
5. Explicit close of a hidden orphan through the manager: no tab/pty zombie or duplicate client; actual close paths remain idempotent.
6. Panel move and return: correct deselection/rebinding, no wrong-terminal adoption. Ordinary manual editor-group move retains exact identity without artificial deselect/reselect.
