# Ответ по этапу 5a1

## Q1. Публичный вход для чистых моделей

**Решение:** изменить D16. Перенести `paneName` в `modules/sessions/paneName.ts` и экспортировать через `@modules/sessions`. Удалить реализацию и экспорт из Pane Editors. Тело функции сохранить без изменений. Модели Sidebar и сценарии получают функцию через публичный вход Sessions.

**Причина:** функция выбирает имя из данных Herdr Pane: label, terminalTitle, затем идентификатор. Она не использует состояние или ресурсы редактора. Поэтому Sessions является допустимым предметным владельцем, как для других правил над снимком. Его публичный вход уже доступен без VS Code. Предыдущее решение D16 не учло загрузку host-зависимых экспортов Pane Editors; исправляем размещение, а не маскируем зависимость тестом.

**Mock не разрешаю для решения этой проблемы.** Подмена `@modules/pane-editors` только в тесте позволяет тесту загрузиться, но чистый производственный модуль по-прежнему требует VS Code. Это не выполняет правило IMPLEMENTATION. Частный production-import, дополнительный публичный вход и lazy loader также не нужны.

## Следствие для D17

`modules/pane-editors` не импортирует Sessions: peer rule сохраняется. Уточнить будущую функцию как `paneTerminalOpenRequest(sessionId, pane, name)`. Вызывающая фича или View вычисляет `name` через `paneName(pane)` из `@modules/sessions` и передаёт его как данные. Функция только собирает запрос открытия. Не дублировать правило имени и не внедрять отдельный сервис именования.

Если чистому потребителю нужен только тип запроса открытия, использовать `import type` из публичного входа Pane Editors. Чистые модели Sidebar не должны импортировать его runtime-функцию сборки запроса.
