### 2. Disposal order in `dispose()`: identical

I simulated `acquire` (`:48-52`). Without `after`, it inserts at index 0. With `after`, it inserts at `indexOf(after) + 1`.

- logger → `[logger]`
- manage → `[manage, logger]`
- popup → `[popup, manage, logger]`
- sessions, sessionsView, configureExecutable, status, selection and focusTracker are each inserted after `popup`, which is at index 0 at that point, so each goes to index 1 → `[popup, focus, selection, status, configExec, sessionsView, sessions, manage, logger]`
- surfaceManager and everything after it go to index 0 → `[revealPane, close, rename, createPane, createSpace, decoration, agents, npmScripts, runNpmScript, spaces, panes, navigationContext, surfaceManager, popup, focus, selection, status, configExec, sessionsView, sessions, manage, logger]`

`HEAD` `dispose()` (`HEAD:209-230`) releases objects in exactly this sequence, with `takeoverPopupHost` between the surface manager and the focus tracker. `npmScripts` is still released before `runNpmScript`, as in `HEAD`.

### 3. Constructor-failure cleanup: identical for every step

- An insertion never reorders elements that are already in the list. So at any step, the list is exactly the final list restricted to the objects acquired so far.
- `HEAD`'s catch ladder (`HEAD:169-190`) is the same fixed sequence, and it skips every variable that is still `undefined`.
- An object is recorded right after its constructor returns. This matches `HEAD`, where the `let` was assigned right after construction (for example `takeoverPopupHost = popupHost` at `HEAD:98` and `paneTerminalSurfaceManager = surfaceManager` at `HEAD:132`). An object whose constructor throws is therefore never released, in both versions.
- At every step from 2 to 25, the set and order of released objects match `HEAD`. A failure inside `new VsCodeLogger` happens outside the `try` in both versions, so nothing is released and the error propagates.
- The catch rethrows the original error (`:117`). If a `dispose()` throws during cleanup, that error replaces the original one in both versions; the slice does not add exception isolation, which is correct.
- Objects without `dispose` are never recorded: `HerdrSettings`, `TakeoverPluginRegistration`, `HerdrPaneClientFactory` and the inner session-directory and connector objects. `HEAD` did not release them either.

### 4. Idempotence and `initialize()`

- `dispose()` keeps the `disposed` guard (`:133-134`).
- `initialize()` still reads only `this.takeoverPluginRegistration` and `this.sessions` (`:123,125`). Both are assigned in the constructor (`:111-112`).

### 5. No over-engineering

There is no container and no framework. The class has four fields (`disposables`, `sessions`, `takeoverPluginRegistration`, `disposed`), and each one is needed after construction. The file shrank from 232 to 139 lines, and the composition now reads top to bottom. The only part that is more general than needed is `after` with `indexOf`: `after` is always `popupHost`, which is always at index 0 when it is used. Hard-coding that would be less readable, so I accept the generic form.

## Corrections

1. **Name the popup-host exception at the point where it is encoded** (`src/extension/HerdrExtension.ts:48`, `:72-78`).
   - **Why:** `acquire(x, popupHost)` reads as "acquire x after the popup host". That is already true in time, so the argument looks like a no-op hint. Nothing says that it puts `x` after `popupHost` in the disposal order. That is the one non-reverse segment that finding G and astra (`answers/final-architecture.md`, G) require to stay explicit. A maintainer who drops the six arguments as noise silently moves the popup host back to plain reverse order, and no test catches it.
   - **Exact correction:** rename the parameter to `disposeAfter`, and add one comment line above `acquire`:

     ```ts
     // Released front to back: reverse construction, except that the objects passed `disposeAfter: popupHost` are released after the popup host, which goes between the surface manager and the focus tracker.
     ```

     Wrap the comment to the file's line length. Do not change the code.
