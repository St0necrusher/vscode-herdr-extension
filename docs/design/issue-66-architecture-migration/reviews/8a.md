## Corrections

### 1. Remove the new try/catch blocks around registrations

- **Where:** `src/views/npm-scripts/VsCodeNpmScriptsView.ts:16-28` and `src/views/sidebar/shared/visiblePaneEditorDecoration.ts:31-41`.
- **Why:**
  - Both blocks add partial-construction cleanup that the old code did not have, and no test exercises it.
  - On `origin/main`, `ScriptsFeature` built the hover view and then registered its commands, with no cleanup if a registration failed. On `HEAD`, the feature's `Disposable.from(registerCommand…)` had none either.
  - The sibling navigation views do the same with no try: `VsCodeSpacesView.ts:18-21` and `VsCodePanesView.ts:46-54` each create a tree view and then register a command.
  - For the decoration provider, the guarded leak is not observable. The only subscriptions are on `navigationContext`, and the `HerdrExtension` catch ladder disposes that object, which clears its listeners (`NavigationContextModel.ts:76-84`).
  - This is defensive code for a case that does not occur (`common.md` rules).
- **Correction:**

  ```ts
  // VsCodeNpmScriptsView constructor body
  this.registrations = vscode.Disposable.from(
    vscode.commands.registerCommand("herdr.runNpmScriptAtCursor", () =>
      this.feature.runNpmScriptAtCursor(this.scriptAtCursor()),
    ),
    vscode.languages.registerHoverProvider({ language: "json", scheme: "file", pattern: "**/package.json" }, this),
  );
  ```

  ```ts
  // VisiblePaneEditorDecorationProvider constructor body
  this.marked = this.markedRows();
  this.subscriptions = [
    context.onDidChange(() => this.updateMarks()),
    visible.onDidChangeVisiblePaneIds(() => this.updateMarks()),
  ];
  this.registration = vscode.window.registerFileDecorationProvider(this);
  ```

  The handler `() => this.feature.runNpmScriptAtCursor(…)` returns the same Promise as the current `async () => { await … }` wrapper. This form matches `ConnectionStatus.ts:37`.

### 2. Make `scriptAtCursor` private

- **Where:** `src/views/npm-scripts/VsCodeNpmScriptsView.ts:51`.
- **Why:** the method was public only so that the feature could call back into the view, and finding E removes that seam. Its only caller is now the view's own command at `:17`, and no test uses it. Keeping it public leaves the old callback API open.
- **Correction:** declare it `private scriptAtCursor(): NpmScriptTarget | undefined`. Keep the comment above it.
