## Blocker requiring coordinator decision

D6 requires directory operations to receive the executable string instead of `HerdrConfiguration`. This conflicts with an assertion the brief explicitly protects:

- `src/features/sessions/SessionsModel.test.ts:333`: `expect(h.start).toHaveBeenCalledWith(configuration, "work");`
- `src/features/sessions/SessionsModel.test.ts:113–117`: the harness creates `start` as a spy and passes that same spy directly as `directory.start`.
- `src/features/sessions/SessionsModel.ts:222`: the production caller currently passes `this.state.configuration` to `directory.start`.
- `src/capabilities/sessions/directory.ts:18`: the existing contract takes `HerdrConfiguration`.

After the required D6 caller change, the spy receives `"herdr"`, not `{ executable: "herdr", session: "default" }`; the unchanged assertion fails. Changing imports or mock parameter annotations cannot resolve this. Wrapping the test spy to reconstruct the old configuration argument would hide the contract change rather than preserve its observable assertion honestly.

**Smallest proposal:** authorize changing only this assertion's argument to `configuration.executable`, alongside the permitted mock construction/signature changes. This is an additional explicit test exception beyond D3 and the CLI construction changes already allowed by the slice. No assertion has been changed pending that authorization.

The common brief says to stop and report when a test cannot retain its assertions. Accordingly implementation and validation were not started; there is no partial migration for the coordinator to unwind.
