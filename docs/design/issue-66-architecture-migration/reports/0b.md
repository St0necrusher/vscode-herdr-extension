## Coordinator review: activation ordering

The test bundle loading before `onStartupFinished` activation is **not guaranteed** by the inspected runner/host implementation:

- `node_modules/@vscode/test-cli/out/cli/platform/desktop.mjs:44–45,74–78` supplies `runner.cjs` as `extensionTestsPath` to test-electron.
- `node_modules/@vscode/test-electron/out/runTest.js:50–90` launches the extension development host with `--extensionTestsPath` and `--extensionDevelopmentPath`; it supplies no activation-order barrier for test modules.
- `node_modules/@vscode/test-cli/out/runner.cjs:11–33` processes preloads/global setup, adds test files, and starts Mocha. The suite's module-load observers are installed only when its bundle is loaded by Mocha.
- In the installed VS Code `1.141.0` host, `.vscode-test/vscode-darwin-arm64-1.141.0/Visual Studio Code.app/Contents/Resources/app/out/vs/workbench/api/node/extensionHostProcess.js`, `_handleEagerExtensions()` schedules `_activateAllStartupFinished()` via `Promise.race([s, Bt(1e4)]).then(...)` while returning `s`. `_startExtensionHost()` opens `_eagerExtensionsActivated` after that returned promise. `$extensionTestsExecute()` waits for that eager-activation barrier before `_doHandleExtensionTests()` loads and runs the runner. `_activateAllStartupFinished()` separately waits for the configuration provider and may defer activation. Therefore startup-finished activation and test loading have independent asynchronous paths, not a test-before-activation guarantee. Evidence is in the named functions around character offsets 1292426–1295980 of that installed minified file.

As requested, `composition.test.ts:5–11` now checks at module load, **before installing any observers**, that the extension exists and `isActive === false`. If already active, it fails with:

```text
Composition test activation-order race: onStartupFinished activated Herdr before the test bundle installed its VS Code registration observers.
```

This makes the requested dependency explicit; it does not prevent the race or claim Linux/xvfb coverage. The corrected suite passed three fresh local host runs in a row. No retries or production changes were added. The `isActive` assertion diagnoses completed early activation; the host API does not expose a separate activation-in-progress flag.
