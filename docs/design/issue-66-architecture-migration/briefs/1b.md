## Goal

Move the Herdr CLI and socket integration into `src/api/herdr/`, with one public entry `src/api/herdr/index.ts`. Afterwards `src/infrastructure/herdr/` no longer exists.

## Placement

- `src/infrastructure/herdr/cli/HerdrCliSessionDirectory.ts` (+ test) → `api/herdr/cli/`.
- `src/infrastructure/herdr/socket/{JsonSocketClient,JsonSocketHerdrSessionConnection,JsonSocketHerdrSessionConnectionFactory,NodeHerdrSocketConnector}.ts` → `api/herdr/connection/`.
- `src/infrastructure/herdr/socket/protocol/*` → `api/herdr/protocol/`, private to the block: the public `index.ts` does not export it.
- Types from `src/capabilities/sessions/*`, split by meaning (D7):
  - Herdr data → `api/herdr/types.ts`: everything in `session.ts` and `snapshot.ts`; `SplitDirection`, `CreatedSpace`, `CreatedPane` from `creation.ts`; `HerdrPaneMovedEvent` from `sessionEvents.ts`.
  - API contracts → beside their part (`connection/`, `cli/`), exported through `api/herdr/index.ts`: `connection.ts` (`HerdrConnectionFailure`, `HerdrConnectionFailureError`, `HerdrSessionProjectionConsumer`, `HerdrSessionConnection`, `HerdrSessionConnectionFactory`) and `directory.ts` (`HerdrSessionListResult`, `HerdrSessionDirectory`).
  - Application types stay where they are for now and move with their owner in later slices: the request types and `ActiveSessionCreation`/`ActiveSessionManagement` (`creation.ts`, `management.ts`), `activeSessionProjection.ts`, `HerdrSessionEventMap`/`EventName`/`EventSource` (`sessionEvents.ts`), `configuration.ts`.
- **Executable path (D6).** `HerdrSessionDirectory` takes the executable path instead of the `HerdrConfiguration` object; its caller reads the configuration before each operation, as today, and passes `executable`. If any API part needs more than the executable from the configuration, stop and report. `HerdrCliSessionDirectory.test.ts` may change construction and call arguments; its assertions stay.
- If an API contract references an application type (for example a connection method taking an application request type with `sessionId`), do not invent a new API type on your own: report the reference with file:line and your smallest proposal, and keep that type where it is for this slice.

Update every consumer in `src/` and `test/` to import from `@api/herdr` (production) or the file directly (tests). Remove each `capabilities/sessions` file that becomes empty and its export line in `capabilities/sessions/index.ts`; no re-export of the moved types from `capabilities`. Delete `src/infrastructure/herdr/` and its alias uses.
