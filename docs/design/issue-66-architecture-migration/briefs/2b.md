## Placement

- **`views/sidebar/sessions/`**: `VsCodeSessionsView` and its trivial clicks `herdr.selectSession`, `herdr.refreshSessions` (registered today in `SessionsFeature`). Create only `views/sidebar/` and its `sessions` part; other sidebar parts come in slice 5a.
- **`views/connection-status/`**: `StatusFeature`, `statusModel` (+ test), `VsCodeStatusView`, the `HerdrStatus*` types (today in `src/features/sessions/capabilities/index.ts`), and the commands `herdr.showStatusActions`, `herdr.retryDiscovery`, `herdr.openSettings`. The `openSettings` body (today in `VsCodeHerdrConfiguration`) moves here.
- **`features/start-local-session/`**: `herdr.start` (today registered in `StatusFeature`), calling `SessionsModel.startSelectedSession()`.
- **`features/configure-executable/`**: `herdr.selectExecutable` and the `selectExecutable` body (open dialog, update `herdr.executable` globally).
- The status quick-pick actions "start" and "select executable" run the same operations as those commands. Views may import features (§1), so connection-status may call the two features directly; pick the simplest way that keeps behavior identical and report it.
- **Settings (D6).** A generic reader and change subscription in a `core/` settings block, parameterised by section and keys, with no Herdr names. The Herdr binding (section `herdr`, keys `executable` and `session`, defaults `herdr`/`default`, trimming and empty-value fallback exactly as `VsCodeHerdrConfiguration.read()` does today, change filter on those two keys) lives in `src/extension/`, implementing `HerdrConfigurationSource` from `@modules/sessions`. `HerdrConfigurationActions` disappears. Delete `VsCodeHerdrConfiguration` and `src/infrastructure/vscode/`.
- **Active Session projection (D15).** `SessionsModel` gains `getActiveSessionProjection()` and `onDidChangeActiveSessionProjection(listener)`: the getter maps its state through `activeSessionProjection`, the subscription wraps its existing `onDidChange`. No second store, no new publish queue, no change to the order existing subscribers are notified in.
- **`HerdrExtension`** builds `SessionsModel`, the views and the features directly, wires the projection source, `subscribe("pane.moved")`, creation and management to the model (what `SessionsFeature` forwarded), and owns their lifecycle: the same initialization order, the same dispose order, the same cleanup on a constructor or `initialize()` failure as `SessionsFeature` and `HerdrExtension` have today. Read both and keep each step.
