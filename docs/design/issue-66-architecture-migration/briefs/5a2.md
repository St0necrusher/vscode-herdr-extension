## Goal

Issue #66: "`Spaces/Panes/Agents/ScriptsFeature` commands | scenario commands → features; trivial clicks (select Space, open Pane, move Tab) → their view"; features `create-space/ create-pane/ rename/ close/ reveal-pane/`. `ARCHITECTURE.md` §2: "Scenario beats surface"; §4: a feature "owns a scenario end to end: prompts, confirmation, execution through modules, consequences across modules, the result and error messages", "never imports view classes", "keeps no copy of module state", "one file per entry"; "A click that calls one module operation is wired by its view". D9: "the feature re-checks the rule on current data before acting". D10: "features and views never import peer features/views; reveal-pane and run-npm-script open an editor through `modules/pane-editors`, not through another feature".

## Placement (command → owner)

| Command | Owner |
|---|---|
| `herdr.selectSpace` | `views/sidebar/spaces` (`SpaceSelectionOperations.selectSpace`) |
| `herdr.openPane` | `views/sidebar/panes` (builds the open request from the current snapshot, calls `PaneTerminalOpening`; silent when the Pane is absent, as now) |
| Tab drag-and-drop move (`moveTab`) | `views/sidebar/panes` (calls `ActiveSessionManagement.moveTab`; shows `showTabMoveError` copy itself) |
| `herdr.createSpace` (folder pick, create, select, open Pane) | `features/create-space` |
| `herdr.createPane`, `herdr.splitPaneRight`, `herdr.splitPaneDown` | `features/create-pane` (`create-pane.ts`, `split-pane.ts`, sharing the create-and-open tail) |
| `herdr.renameSpace`, `herdr.renameTab`, `herdr.renamePane` | `features/rename` (`rename-space.ts`, `rename-tab.ts`, `rename-pane.ts`) |
| `herdr.closePane`, `herdr.closeTab`, `herdr.closeSpace`, `herdr.closeGroup` | `features/close` (one file per entry; confirmations, Herdr close, then `PaneTerminalClosing.closePanes` only after Herdr confirms) |
| `herdr.openAgentPane` (select Space + open Pane across two modules) | `features/reveal-pane` |

Rules: each feature block has an `index.ts` and one public class that registers its commands (like `features/start-local-session`). Prompts, confirmations and error messages move out of the views into the features that use them; copy text stays byte-identical. Features read current data from `@modules/workspace-context` (`NavigationContextSource`) and never from the tree models. Close re-checks on current snapshot data: closable Pane/Tab through the 5a1 `modules/sessions` rule, Close Group through `worktreeGroup`; preserve each existing guard exactly (e.g. Close Tab also requires that the Tab holds more than one Pane, as `PanesFeature.closeTab` does via `kind === "group"`; list in the report where each guard now lives).

Command arguments: the sidebar passes tree items today. A feature must not import view classes, so it narrows the argument structurally to plain data (`{ spaceId }`, `{ paneId }`, `{ tabId }`); the tree items expose those properties (`PanesGroupTreeItem` gets a `tabId`; `group.tab.id` stays what it was). Extension tests still pass real tree items, which satisfy this. Ask in the report (D14) if a test cannot keep its assertions.

Opening a Pane (D10): add to `modules/pane-editors` a function `paneTerminalOpenRequest(sessionId, pane)` (uses the 5a1 `paneName`) exported from its entry; features and the view look the Pane up in their current context state and call `PaneTerminalOpening`; create-space/create-pane/split keep today's "Pane absent from the snapshot" error and message (`Pane <id> is not in the current Session snapshot`). `NavigationPaneOpening` and `features/navigation/capabilities/` are deleted: `ScriptsFeature` (5b's code) gets a minimal edit to take `PaneTerminalOpening` and build the request the same way, so its tests keep their assertions.
