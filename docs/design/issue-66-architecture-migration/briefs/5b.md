## HerdrExtension composition

Delete `NavigationFeature`, `NavigationFeatureDependencies` and `src/features/navigation/`. No replacement facade or grouping class. `HerdrExtension` builds, in exactly this order after `surfaceManager` (`sessionOwner` = sessions, `surfaceManager` = opening/closing/presence):

1. `context = new NavigationContextModel(sessionOwner, surfaceManager)` (`@modules/workspace-context`)
2. `VsCodePanesView(context, context, surfaceManager, sessionOwner)`
3. `VsCodeSpacesView(context, context)`
4. `VsCodeNpmScriptsView(context)`, then `RunNpmScriptFeature(context, sessionOwner, surfaceManager, view)` (creation = `sessionOwner`; keep the view-then-commands order of old `ScriptsFeature`)
5. `VsCodeAgentsView(context, context)`
6. `VisiblePaneEditorDecorationProvider(context, context)`, then `vscode.window.registerFileDecorationProvider(provider)`
7. `CreateSpaceFeature(context, context, sessionOwner, surfaceManager)`, `CreatePaneFeature(context, sessionOwner, surfaceManager)`, `RenameFeature(context, sessionOwner)`, `CloseFeature(context, sessionOwner, surfaceManager)`, `RevealPaneFeature(context, context, surfaceManager)`

Check the argument lists against the current `NavigationFeature.ts`; they win over this list. Disposal is the reverse of construction: revealPane, close, rename, createPane, createSpace, decorations, decorationProvider, agents, runNpmScript feature, npm-scripts view, spaces, panes, context; then the existing disposals of `HerdrExtension` after navigation. The constructor-failure `catch` disposes whatever was built, in the same order, as `navigation?.dispose()` does today (flat `let x: T | undefined` style of the existing constructor; if one `new` throws, earlier pieces are disposed). Keep `dispose()` idempotent via the existing `disposed` flag.
